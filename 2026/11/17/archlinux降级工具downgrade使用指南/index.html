ArchLinux降级工具downgrade使用指南

发表于： 2026-11-17

前言

downgrade 是 Arch Linux 生态中专用于将已安装软件包回退到历史版本的工具。它本身是一个 Bash 脚本，同时检索本地 pacman 缓存与 Arch Linux Archive（ALA），列出可用的旧版本供交互式选择，省去了手动查找、下载和安装 .pkg.tar.zst 文件的步骤。

本文先系统介绍 downgrade 的安装、核心用法与常用选项，再以一个完整的应用案例——降级 Hugo 以恢复对 hugo-next 旧版主题的兼容性——来展示其实际工作流程。

安装 downgrade

downgrade 位于 AUR，使用惯用的 AUR helper 安装即可：

1
2
3

yay -S downgrade
# 或
paru -S downgrade

也可以从 AUR 手动构建：

1
2
3

git clone https://aur.archlinux.org/downgrade.git
cd downgrade
makepkg -si

核心用法

交互式降级（默认行为） 

1

sudo downgrade <package_name>

运行后，downgrade 会合并本地 pacman 缓存（/var/cache/pacman/pkg/）和Arch Linux Archive 中的可用版本，在终端中列出供你选择。用方向键选中目标版本，确认后即完成安装。如果本地缓存中恰好保留了旧版本，它会优先出现在列表中，安装速度也更快。

直接指定目标版本

跳过交互选择，一步到位：

1

sudo downgrade 'hugo=0.145.0'

版本号写法的准确性取决于 ALA 和缓存中的条目命名。如果 0.145.0 存在歧义，可以带上完整的 pkgrel，如 'hugo=0.145.0-1'。

常用选项

选项作用
--ala-only仅从 Arch Linux Archive 检索，忽略本地缓存
--cached-only仅从本地 pacman 缓存检索
--prefer-cache缓存与 ALA 同时命中时优先使用缓存
--latest / --oldest在多个候选中自动取最新或最旧的一个，减少交互
--ignore never降级后不自动将包加入 IgnorePkg，交由你自己决定

--ala-only 适合在缓存已被清理、但确实需要 ALA 中某个历史版本的场景；--ignore never 则在你不确定是否应该锁定版本时提供了更谨慎的选择。

底层原理简述

downgrade 本身不发明新的包管理机制，它最终调用的仍是 pacman -U。区别在于它替你做完了这些事：检索缓存与 ALA、按版本排序并展示、下载远程包文件、调用 pacman -U 安装。理解这一点，有助于在 downgrade 遇到依赖问题时知道该往哪里排查。

应用案例：降级 Hugo 以恢复 hugo-next 主题兼容性

问题背景

Hugo 在 v0.146.0 中重写了模板系统，layouts 目录的结构与查找逻辑发生了破坏性变更。hugo-next 主题从 4.8.0 版本开始才适配新系统，并要求 Hugo ≥ 0.146.0（Extended 版）。在此之前，该主题仅支持到 0.145.x；社区中已验证 v0.146.x 开始不可用，0.145.0 是旧版主题可以正常工作的最后一个稳定版本。Hugo 社区的建议同样是：如果主题尚未跟进，应暂时停留在 v0.145.0。

因此，当 pacman 将 Hugo 升级到 0.146.0 以上后，旧版 hugo-next 主题的站点构建就会失败。此时需要用 downgrade 将 Hugo 回退到 0.145.0，并阻止后续更新再次将其拉回新版。

下文中以 hugo 包为例。如果你安装的是 hugo-extended（部分主题强制要求 Extended 版），请将命令中的 hugo 统一替换为 hugo-extended，或两个包一并处理。

确认目标版本 

1

hugo version

假设当前已升级到 0.146.4，目标为 0.145.0。如果需要确认主题侧的兼容上限，可以查看主题的 theme.toml 或仓库 release 说明中声明的 Hugo 最低/最高版本要求。

使用 downgrade 执行降级 

1

sudo downgrade 'hugo=0.145.0'

downgrade 会从缓存或 ALA 中找到 hugo-0.145.0 的包文件并安装。安装完成后验证：

1
2

hugo version
# 应显示 hugo v0.145.0+extended ...

如果指定版本未命中，去掉版本号改用交互式 sudo downgrade hugo，在列表中手动挑选。

锁定版本，阻止 pacman 再次升级

downgrade 在降级完成后通常会询问是否将包加入 IgnorePkg。无论是否在交互中选择了“是”，都建议手动核查 /etc/pacman.conf：

1
2

[options]
IgnorePkg = hugo

如果同时涉及 hugo-extended，写作 IgnorePkg = hugo hugo-extended 即可。Arch Wiki 同样建议在降级确认可用后，将包加入 IgnorePkg，直到上游兼容性问题得到解决。

修改前建议先备份配置文件：

1

sudo cp /etc/pacman.conf /etc/pacman.conf.bak

验证锁定是否生效：

1
2
3

sudo pacman -Syu
# 输出中应出现类似：
# warning: hugo: ignoring package upgrade (0.145.0-1 => 0.146.4-1)

回到站点验证构建 

1
2

cd /path/to/your/hugo-site
hugo server

如果站点正常渲染、主题样式和功能恢复，说明降级与锁定均已到位。

注意事项

downgrade 不是“跳过依赖检查”的万能工具。 downgrade 底层仍调用 pacman -U，处理依赖变更但不解决版本冲突。Hugo 作为独立的静态二进制，降级通常不涉及 soname 变更，风险较低；但降级其他涉及共享库的包时，需要根据 pacman 的提示同步处理依赖。

IgnorePkg 是临时手段，不是长期方案。 锁定 hugo 意味着放弃该包的安全更新与功能改进。一旦 hugo-next 主题升级到 4.8.0 以上并确认兼容 Hugo 0.146.0+，就应从 /etc/pacman.conf 中移除对应条目，恢复正常滚动更新。

临时单次升级测试。 如果需要在保留锁定的前提下试用新版 Hugo，可以用 sudo pacman -Syu --ignore=hugo 跳过本次升级，但这不会改变 IgnorePkg 的持久锁定状态。测试完成后如需回到 0.145.0，再次执行 sudo downgrade 'hugo=0.145.0' 即可。

降级后重启受影响的进程。 与升级类似，已经在运行的进程不会自动切换到降级后的二进制或库。如果降级的是服务端程序或库，需要重启对应进程才能使降级生效。
